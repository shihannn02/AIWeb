# 串联策略分析（serial-strategy）

## 何时使用

- 已完成分箱和变量筛选（如 `feature-filter`），得到候选变量列表
- 用户选定了要用的变量，需要自动查找阈值边界并做串联分析
- 输出准入分析结果 Excel（单一Sheet：汇总表 + 增益效果明细）

## 工作流程

```
用户选定变量 → 查找分箱边界形成规则 → 选择排序方式 → 串联分析 → 输出 Excel
```

### 第一步：用户输入选定的变量

用户需提供：
1. **分箱结果 Excel 路径**（含 Train分箱明细 Sheet）
2. **筛选结果 Excel 路径**（含候选变量汇总 Sheet，`feature-filter` 输出）
3. **选定的变量列表**（如 `['phone_cnt_call_1h', 'olc_qry_empty_cnt_phone']`）
4. **可选：阈值方向覆盖**（如某变量想用头箱而非尾箱，可单独指定）

### 第二步：自动查找阈值边界

对每个选定变量：
1. 从 Train分箱明细 读取该变量的全部分箱
2. 排除特殊值箱（缺失/空值/特殊）
3. 判断高坏箱在头端还是尾端（与 `feature-filter` 的 head/tail 判定一致）
4. 提取该箱的边界值作为拒绝规则阈值

### 第三步：形成拒绝规则

| 方向 | 规则表达式 | 示例 |
|------|-----------|------|
| 尾箱高（尾箱坏率 > 头箱坏率） | `变量 > 尾箱下限` | `phone_cnt_call_1h > 1.0` |
| 头箱高（头箱坏率 >= 尾箱坏率） | `变量 <= 头箱上限` | `olc_qry_first_days_pkgx_phone <= 3.0` |

### 第四步：选择排序方式（询问用户）

运行前询问用户排序偏好，提供三种选项：

| 序号 | 排序方式 | 适用场景 |
|------|---------|---------|
| 1 | 按人数降序 | 优先覆盖更多人群，策略覆盖面优先 |
| 2 | 按坏率降序 | 优先最强区分力的规则，lift 最大化优先 |
| 3 | **按用户指定顺序** | 用户对业务逻辑有明确排列意图，固定优先级 |

**推荐做法**：先询问用户偏好，默认按人数降序。如果用户明确指定了变量顺序，使用"按用户指定顺序"（不重排）。

**关键指标定义：**

| 指标 | 含义 | 计算方式 |
|------|------|---------|
| `规则命中` | 全量数据中满足规则的总人数 | `df.query(expr).shape[0]` |
| `命中人数` | 串联到当前环节实际能命中的人数 | 前序已拒的不再计入 |
| `坏比率(串行)` | 串联实际命中者的坏率 | `串联命中者逾期数 / 串联命中人数` |
| `lift` | 串联坏率 / 大盘坏率 | 衡量规则区分能力 |
| `lift_2` | 串联坏率 / 前序剩余人群坏率 | 衡量在当前剩余人群中的额外区分力 |

**规则丢弃条件（任一满足则丢弃）：**
- `lift < 1.10`
- `命中人数 < 5`

### 第五步：输出 Excel

单一Sheet 格式，包含：

```
                   现数据    调整后
总单数              191      123
逾期单数            109       58
件数逾期率         57.07%   47.15%
通过率            100.00%   64.40%

增益效果：
上线：                        总样本  lift  badrate  规则命中  命中人数  拒绝率  坏客数  坏比率(串行)  lift_2  剩余样本数
phone_cnt_call_1h > 1.0       191  1.39  79.31%     29       29   15.18%   23    79.31%    1.39    162
olc_qry_empty_cnt_phone > 1   191  1.29  80.00%     20       15    7.85%   11    73.33%    1.38    147
```

## 脚本

| 脚本 | 说明 |
|------|------|
| `scripts/serial_strategy.py` | 主脚本：用户交互式输入 → 查找阈值 → 串联分析 → 输出 Excel |

## 使用方式

```bash
python serial-strategy/scripts/serial_strategy.py
```

交互式输入：
1. 分箱结果 Excel 路径
2. 原始数据路径（含标签列）
3. 标签列名
4. 排序方式（1=按人数 / 2=按坏率 / 3=按指定顺序）
5. 用户选定的变量列表（逗号分隔）
6. 原拒绝阈值（如 0.6 = 60%）
7. 输出路径
8. 规则中出现的 `#` 列名自动替换为 `_`

## 常见陷阱

- **头尾5%分箱输出中文列名**：脚本内建列名映射（`变量英文名` → `feature`，`%Bad_Rate` → `bad_rate` 等）
- **`#` 列名破坏 pandas query**：自动替换 `#` 为 `_`
- **箱数少于预期**：test 某些箱内样本数为 0 时 groupby 不生成该行，属正常
- **特殊值箱不参与头/尾判定**：缺失/空值/特殊值单独成箱，跳过
- **字符串排序 vs datetime 排序**：`(-inf, 0.0]` < `[1.0]` < `(1.0, inf)` 字符串排序与数值排序一致，可放心用
- **变量高度重叠导致串联失效**：布尔型变量（`> 0` 或 `<= 0` 阈值）在串联中极易完全重叠——比如 `olc_qry_cnt_7d_phone > 0` 和 `olc_qry_hit_7d_flag_phone > 0` 命中的是同一批人，第一条规则已拒绝，第二条规则串联剩余0人。解决方案：(a) 选变量时优先选不重叠的变量族；(b) 用 `按用户指定顺序` 让用户控制排列；(c) 在预览阶段告知用户哪些变量高度重叠
- **多变量 > 0 阈值陷阱**：OLC 系列中 qry_cnt、hit_flag、last_empty_flag 等多变量共享同一底层数据源，阈值都是 `> 0`，实为同一信号的不同变形。串联时通常只有第一个生效，其余 lift=0 被丢弃。建议先做变量去重再串联
